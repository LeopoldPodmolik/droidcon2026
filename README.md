# Develop Smarter, Not Harder

## Shipping Peacock's live NBA features from Prague — DroidCon 2026

Support files for the talk by **Leopold Podmolík**, Senior Android Developer at Sky CZ.

Everything shown on stage — examples, demos, configs — is here, so you don't need to photograph the slides.

> If you repeat it, **automate** it. If you wait for it, **mock** it. If it's tedious, let **AI draft** it. But **you review** it.

---

## 🏀 The Problem

Live sport is hard to build against:

- A real NBA game exists only a few nights a week.
- Score, clock, and game state change second by second.
- The data comes from backends we don't own.
- It has to be right across markets, devices, and network conditions — errors and late-game states included.

All examples use a fictional **NBA GameDay** app (live scores, player stats, schedule, standings) instead of the real Peacock Courtside Live feed. The data is generated by AI.

## 🚀 Quick Start

### 1. Run the mock server

```bash
cd mock-server
npm install
npm start          # http://localhost:3000
```

Or straight from the OpenAPI spec, no code:

```bash
npm install -g @stoplight/prism-cli
prism mock mock-server/openapi.yaml --port 4010
```

Endpoints, error simulation (`?_error=403`), and test commands: [`mock-server/README.md`](mock-server/README.md).

### 2. Point Postman at it

Import [`postman/environments/localhost.json`](postman/environments/localhost.json) and select **NBA GameDay — Localhost**. Every request in the Postman guides then runs against `http://localhost:3000`.

### 3. Route the app through Proxyman

The Android app always calls the production URL, `https://api.nbagameday.com`. In Proxyman, add a **Map Remote** rule from `https://api.nbagameday.com/*` to `localhost:3000`, so the app talks to the mock server without a code change. Step by step: [`proxyman/01-map-local.md`](proxyman/01-map-local.md).

### 4. Run the Android app

Open [`android/`](android/) in Android Studio and run the `app` configuration on an emulator with the Proxyman certificate installed.

### 5. Connect the AI agent

Paste [`ai/servers/cursor.mcp.json`](ai/servers/cursor.mcp.json) into `~/.cursor/mcp.json`. Proxyman MCP runs locally and needs the Proxyman app open. Postman MCP is remote and signs in with OAuth on the first call. Details: [`ai/02-setup.md`](ai/02-setup.md).

## 🔧 Quick Reference — When to Use What

| Scenario | Tool | Feature |
|----------|------|---------|
| Run an API that doesn't exist yet | **Prism / Express** | Mock server from OpenAPI |
| Reuse requests with different data | **Postman** | Variables |
| Switch between local / alpha / beta / prod | **Postman** | Environments |
| Auto-generate tokens, timestamps | **Postman** | Pre-request Scripts |
| Send prod traffic to the local mock | **Proxyman** | Map Remote |
| Test against an API that doesn't exist | **Proxyman** | Map Local |
| Simulate error codes (403, 500, 429) | **Proxyman** | Map Local |
| Modify specific fields in a live response | **Proxyman** | Scripting |
| Inject new fields to test upcoming features | **Proxyman** | Scripting |
| Simulate state transitions (scheduled → live) | **Proxyman** | Scripting |
| Let the agent read a captured session | **Proxyman MCP** | `get_flows`, `filter_flows` |
| Draft a Map Local or a response script | **Proxyman MCP** | `create_map_local`, `create_scripting_rule` |
| Scaffold a collection or environment | **Postman MCP** | `createCollection`, `createEnvironment` |
